# Ривер

Браузерный безлимитный техасский холдем для 2–6 человек. Стартовый стек — 1 000 виртуальных фишек, блайнды — 5/10. Введите ник и нажмите **Быстрая игра** либо откройте комнату для друзей. Приватную комнату можно открыть по шестизначному коду или по кнопке **Скопировать приглашение**.

## Локальный запуск

Из корня репозитория, с Node.js 24 и npm:

```sh
npm ci
npm run dev
```

Откройте [игру на localhost](http://localhost:5173). Vite слушает порт 5173, дилер — 3001. Для проверки вдвоём на одном ПК откройте второе окно в отдельном профиле браузера или в режиме инкогнито. Для двух ПК в одной сети используйте адрес первого ПК и порт 5173. Оба порта должны быть доступны по сети. В локальной конфигурации клиент обращается к дилеру по тому же имени хоста, что и страница.

## За столом

- Быстрый подбор случайно выбирает публичный стол со свободным местом. Первыми рассматриваются столы, за которыми один человек ждёт соперника. Проверка и занятие места выполняются в одном синхронном обработчике сервера.
- Дилер запускает раздачу автоматически. Вошедший позже участвует со следующей раздачи. Игрок с нулевым стеком может наблюдать или выйти и заново сесть со стартовым стеком.
- «Уравнять» показывает доплату в фишках. «Повысить до» показывает итоговую ставку за текущий круг. Олл-ин также показывает итоговую ставку за круг. Таймер даёт 30 секунд, затем дилер выполняет чек либо пас. Между раздачами проходит около 4,5 секунды.
- При равных комбинациях выигрыш делится. Нечётные фишки получают победители по часовой стрелке от кнопки дилера. При нескольких размерах олл-ина каждый слой банка распределяется между имеющими на него право игроками.
- Обновление страницы сохраняет место в той же вкладке. После обрыва связи сервер резервирует его на две минуты. В это время таймер хода продолжает идти. Создатель комнаты может уйти в любой момент.
- Сервер хранит комнаты, стеки и ключи восстановления **в памяти одного процесса**. Перезапуск или остановка сервиса удаляет комнаты и обрывает текущие раздачи. После перезапуска создайте новый стол и отправьте новое приглашение.

## Устройство

React, TypeScript и Vite отвечают за клиент. Node.js и Socket.IO ведут игру на сервере. Перемешивание Фишера — Йетса использует `crypto.randomInt`. Сервер проверяет игрока, уникальный идентификатор хода, срок и сумму. Первое принятое действие меняет идентификатор хода, поэтому повторное или запоздавшее сообщение теряет силу. Адресная рассылка содержит собственные карты игрока, общий борд и открывшиеся на вскрытии руки. Колода остаётся на сервере.

- `server/game.ts` — позиции, торговля, таймер хода в состоянии игры и распределение банков.
- `server/rank.ts` — оценка лучшей комбинации из семи карт.
- `server/index.ts` — комнаты, сессии, рассылка и расписание дилера.
- `src/` — лобби, стол и элементы управления.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
```

Для сквозных тестов под Windows нужен установленный Google Chrome. На Linux установите браузер командой `npx playwright install --with-deps chromium`. Можно задать `PW_CHANNEL=chrome`, чтобы использовать установленный Chrome. Playwright запускает отдельный игровой сервер на порту 3011 и статический сервер на 5181, собирает клиент в `dist-e2e/` и проверяет его под путём `/poker/`. Рабочую комнату локального приложения тесты не используют.

Проверки движка охватывают порядок ходов один на один, минимальное повышение, короткий олл-ин, три разных стека, ничью с нечётной фишкой, победу без вскрытия и сохранение фишек в 200 случайных раздачах. Сквозные сценарии покрывают приглашение, обновление в свой ход, повтор одного сетевого сообщения со ставкой, выплату после ривера, быстрый подбор, одновременные заявки, таймер и шестиместный стол на 1366×768 и 1920×1080.

## Публикация

1. Отправьте ветку `main` этого репозитория в свой GitHub-репозиторий. Клиент и сервер находятся в одном дереве исходников.
2. В Render выберите **New → Blueprint**, подключите репозиторий и примените [render.yaml](render.yaml). Укажите `CLIENT_ORIGIN` равным origin сайта Pages, например `https://YOUR-ACCOUNT.github.io` без пути и завершающего слеша. Blueprint создаёт один Node Web Service. Render передаёт `PORT` автоматически. Убедитесь, что корень сервиса отвечает `River OK`. [Спецификация Render Blueprint](https://render.com/docs/blueprint-spec)
3. В GitHub **Settings → Pages → Build and deployment** выберите **GitHub Actions**. В **Settings → Secrets and variables → Actions → Variables** добавьте переменную репозитория `VITE_SERVER_URL` с фактическим HTTPS-адресом сервиса Render.
4. Запустите **Actions → Publish poker client → Run workflow** либо отправьте новый коммит в `main`. Workflow проверит движок, соберёт клиент и опубликует каталог `dist/`. [Руководство Vite по GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages)
5. Откройте адрес из результата шага Deploy. Создайте приватную комнату и войдите из второго профиля по приглашению. У приглашения вид `/имя-репозитория/#room=КОД`. Относительные пути сборки и фрагмент адреса сохраняют маршрут при обновлении страницы.

Для собственной локальной конфигурации скопируйте `.env.example` в `.env.local` и задайте `VITE_SERVER_URL` до запуска или сборки Vite. Сервер читает `PORT` и `CLIENT_ORIGIN` из окружения процесса.

## Визуальные референсы

Лобби оформлено по [русской версии PokerStars](https://www.pokerstars.net/ru/?&no_redirect=1): панорамный баннер, крупный сжатый заголовок и округлые кнопки. Баннер с картами и фишками создан для «Ривера». Roboto и Roboto Condensed с кириллицей поставляются вместе с клиентом. Лицензии включены в каталог `public/licenses/`.

У PokerTH изучены места вокруг стола, история дилера и сумма колла на кнопке. У настольного PokerStars в теме Nevada — расположение собственной руки и отдельный блок повышения ставки. Для игры выбраны зелёное сукно, светлые карты и золотая подсветка активного места. Рисунок рубашки, карты и сукно сделаны средствами CSS.

- [PokerTH — игровой стол с панелью ставок](https://www.spiele-umsonst.de/pokerth-t3726.html)
- [PokerStars — скриншоты настольной темы Nevada](https://pokerenergy.net/nevada-theme)
